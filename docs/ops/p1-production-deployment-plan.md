# Shaxda V1.0 — P1 Production Deployment Plan (`https://shaxda.app`)

## Context

Shaxda is feature-complete for V1.0 (local hot-seat, guest online play over Durable
Objects, PWA, Somali content). The remaining work is Phase 4 / P1: get the current
working game onto `https://shaxda.app`.

The repository is production-shaped but was built against **placeholder hostnames**
(`shaxda.so` / `api.shaxda.so`). Nothing in the repo points at the real domain, and
no production Cloudflare resources exist yet. This plan covers only the deployment:
no new features, no redesign, no `/legal`, no marketing work.

**Decisions taken from Mahamed in planning:**

- one public hostname, `shaxda.app` — no `api.shaxda.app`;
- Turnstile enabled at launch;
- temporary `*.workers.dev` preview and smoke test before attaching `shaxda.app`;
- current external state: domain purchased at Namecheap, **nothing else done**.

## 2. Actual repository architecture

Two independent Workers, deployed separately, sharing `packages/game-engine` and
`packages/shared`.

**Web Worker — `shaxda-web`** (`web/wrangler.jsonc`)

- Entry: `.svelte-kit/cloudflare/_worker.js`, generated by `@sveltejs/adapter-cloudflare` v7.
- One binding: `ASSETS` → `.svelte-kit/cloudflare`. No DOs, no secrets, no D1.
- `nodejs_compat`, `compatibility_date = 2026-07-05`, `workers_dev: false`.
- All seven routes are `prerender = true`; `/local` and `/online` additionally set
  `ssr = false`, so gameplay is fully client-rendered and never calls the Worker.
- PWA (`@vite-pwa/sveltekit`, generateSW): precaches 70 entries, `start_url: "/"`,
  `navigateFallback: "/local"` restricted by `navigateFallbackAllowlist: [/\/local$/]`.

**API Worker — `shaxda-worker`** (`worker/src/index.ts`)

| Route                 | Purpose                                                                                            |
| --------------------- | -------------------------------------------------------------------------------------------------- |
| `GET /health`         | liveness; returns `{ok:true, service:"shaxda"}`; used by the Playwright web server                 |
| `OPTIONS /rooms`      | CORS preflight, 204                                                                                |
| `POST /rooms`         | Turnstile verify → `RoomCoordinator` reserve → `MatchRoom` init → `{type:"roomCreated", roomCode}` |
| `GET /rooms/:code/ws` | validates room code, requires `Upgrade: websocket`, forwards to the `MatchRoom` DO                 |
| anything else         | 404 JSON                                                                                           |

It also exports the two DO classes (`MatchRoom`, `RoomCoordinator`).

**Request flow**

```
browser ──HTTPS──► shaxda-web (static + prerendered HTML/JS)
   │
   ├── POST /rooms ──────────► shaxda-worker ──► RoomCoordinator DO (global, rate limits)
   │                                        └──► MatchRoom DO (idFromName(roomCode)) init
   └── WSS /rooms/:code/ws ──► shaxda-worker ──► MatchRoom DO (ctx.acceptWebSocket)
```

`web` and `worker` are wired together only by the build-time public variable
`PUBLIC_WORKER_ORIGIN` (`web/src/lib/online/workerOrigin.ts`).

## 3. Recommended Cloudflare topology

Smallest topology that satisfies "one hostname" while preserving both Workers,
both DO classes, and every existing test.

`shaxda.app` is attached to **both** Workers via zone routes, with the API Worker on
more-specific patterns. Cloudflare resolves the most specific matching route first.

```
                        shaxda.app  (Free zone, proxied)
                              │
        ┌─────────────────────┴──────────────────────┐
        │ route: shaxda.app/rooms*                   │ route: shaxda.app/*
        │ route: shaxda.app/health                   │
        ▼                                            ▼
  shaxda-worker  (Workers Paid)               shaxda-web
   ├─ MATCH_ROOM        → MatchRoom DO         └─ ASSETS → .svelte-kit/cloudflare
   ├─ MATCH_COORDINATOR → RoomCoordinator DO
   ├─ var  ALLOWED_ORIGIN
   └─ secret TURNSTILE_SECRET
```

**Why routes rather than Custom Domains:** a Custom Domain claims the entire
hostname for one Worker, so `shaxda.app` cannot be a Custom Domain on `shaxda-web`
and also route `/rooms*` to `shaxda-worker`. Routes support per-path splitting.
The cost is one manual step: routes do not create DNS, so a proxied placeholder
record for the apex is required (section 11).

Same-origin also makes the existing CORS layer a no-op rather than a risk surface.

**Documented fallback (only if apex routing misbehaves):** revert to two Custom
Domains, `shaxda.app` (web) and `api.shaxda.app` (worker). That is a two-line config
change, needs no placeholder DNS, and is the shape the repo and e2e already assume.


**B3 — create untracked `web/.env.production`** (gitignored by `.env.*`, so it never
lands in a commit):

```
PUBLIC_SITE_ORIGIN=https://shaxda.app
PUBLIC_WORKER_ORIGIN=https://shaxda.app
PUBLIC_TURNSTILE_SITE_KEY=<turnstile-site-key>
PUBLIC_CF_BEACON_TOKEN=<web-analytics-token-or-empty>
```

This is the **single most dangerous item in the launch**. Both fallbacks are silent:

- `web/src/lib/online/workerOrigin.ts:1` falls back to `http://127.0.0.1:8787`, so a
  build without `PUBLIC_WORKER_ORIGIN` ships a site whose online mode calls
  `http://127.0.0.1:8787` and `ws://127.0.0.1:8787` — blocked as mixed content, and
  unreproducible on localhost or `*.workers.dev`;
- `web/src/lib/site/metadata.ts:1` falls back to `https://shaxda.example`, poisoning
  every canonical URL, `og:url`, and `og:image`.

Neither fails the build. Verification is by grepping the built output (step 3 of the
sequence), not by trusting the build to complain.

**B4 — `docs/ops/launch-runbook.md`**: replace `shaxda.so` / `api.shaxda.so` with the
final `shaxda.app` topology so the runbook and the config stop disagreeing.

### `locationHint` finding (item 20 — report only, do not change)

There is **no `locationHint` and no `jurisdiction`** anywhere in the repository.

- A match DO is first created in `worker/src/index.ts:110-118` —
  `env.MATCH_ROOM.idFromName(roomCode)` followed by `room.fetch(/internal/rooms/init)`,
  inside `POST /rooms`. With `idFromName` and no hint, Cloudflare places the object
  near the **first request that touches it**, i.e. near the player who created the room.
- The `RoomCoordinator` is different and more consequential: it is a **single global
  object**, `idFromName("global")` (`worker/src/index.ts:15,80-82`), on the hot path of
  _every_ room creation worldwide. It is placed near whoever creates the very first
  room after deploy, and stays there.

Consequence: a room created in Mogadishu is placed at the nearest DO-capable region
(Middle East / Western Europe), so a Minneapolis or London opponent pays one
cross-region hop per move, and the reverse for diaspora-hosted rooms. Shaxda is
turn-based with no clock, so this is a comfort issue, not a correctness one. Room
_creation_ latency additionally includes one round trip to the global coordinator,
wherever that landed. Recorded for post-launch tuning only.

## 7. Turnstile configuration

**Frontend** — `web/src/routes/online/+page.svelte`

- Explicit render against `https://challenges.cloudflare.com/turnstile/v0/api.js?render=explicit`, loaded lazily on mount (line 309-336).
- Site key: `import.meta.env.PUBLIC_TURNSTILE_SITE_KEY` (line 71).
- `turnstileRequired = siteKey.length > 0` (line 72). If the key is empty the widget
  is never rendered and no token is sent.
- Token is passed to `createRoom(turnstileToken)`; the widget is reset on failure.

**Backend** — `worker/src/turnstile.ts` + `worker/src/index.ts:71-78`

- `verifyTurnstile(token, env.TURNSTILE_SECRET, ip)` posts to
  `https://challenges.cloudflare.com/turnstile/v0/siteverify` with `remoteip` from
  `CF-Connecting-IP`.
- **`if (!secret) return true`** — verification is bypassed entirely when the secret
  is unset. That is intentional for local dev and Miniflare tests.
- Failure → `403 {"error":"turnstileFailed","code":"turnstileFailed"}`.

**Required configuration**

| Key        | Where                                                                               | Type             |
| ---------- | ----------------------------------------------------------------------------------- | ---------------- |
| Site key   | `PUBLIC_TURNSTILE_SITE_KEY` in `web/.env.production` (baked into the client bundle) | public           |
| Secret key | `TURNSTILE_SECRET` on `shaxda-worker` via `wrangler secret put`                     | encrypted secret |

**Hostnames to authorize on the widget:** `shaxda.app`. Add nothing else; for the
`workers.dev` preview stage use Cloudflare's **always-passing test keys** instead
(site `1x00000000000000000000AA`, secret `1x0000000000000000000000000000000AA`), which
work on any hostname and exercise the full code path without adding a throwaway
hostname to the production widget.

**Does missing Turnstile config block deployment?** No — both Workers deploy and the
site loads. But the two halves are coupled and a mismatch is silent:

| Site key  | Secret  | Result                                                                                            |
| --------- | ------- | ------------------------------------------------------------------------------------------------- |
| set       | set     | correct — widget shown, token verified                                                            |
| **unset** | **set** | **room creation fails 100% with `turnstileFailed`** — no widget renders, so no token is ever sent |
| set       | unset   | widget shown, token accepted without verification (no abuse protection)                           |
| unset     | unset   | no widget, no verification (dev/preview behaviour)                                                |

Set both, or neither. Never the secret alone.

## 11. Manual actions required from Mahamed

In execution order. Nothing here is something Wrangler could safely do from repo
configuration.

1. **Cloudflare account** — create or sign in. Record the Account ID.
2. **Add site** → `shaxda.app` → select the **Free** plan. Copy both nameservers.
3. **Namecheap** → Domain List → `shaxda.app` → Manage → Nameservers → **Custom DNS**
   → paste both Cloudflare nameservers → save.
   - **Wait:** usually 5 min – 2 h; the registrar's stated limit is 24–48 h.
   - _Still pending_ = Cloudflare shows "Pending Nameserver Update" and
     `dig NS shaxda.app @1.1.1.1` returns Namecheap's nameservers.
   - _Actually broken_ = still pending after 48 h, or the returned nameservers do not
     match what Cloudflare issued (typo / only one of the two saved).
4. **Workers & Pages → Plans → Workers Paid** ($5/mo). Durable Objects and
   SQLite-backed DO storage do not exist on the free plan. **Keep the zone on Free** —
   no Pro/Business, no Argo, no Load Balancing, no Bot Management, no ACM.
5. **SSL/TLS → Overview** → set encryption mode to **Full (strict)**;
   **Edge Certificates** → enable **Always Use HTTPS**.
   - **Wait:** Universal SSL usually issues within 15 min of activation, up to 24 h.
   - _Still pending_ = "Pending Validation" on the edge certificate; because
     `shaxda.app` is HSTS-preloaded, the site is **completely unreachable** during this
     window rather than falling back to HTTP. That is expected.
   - _Actually broken_ = "Validation Timed Out", or > 24 h after zone activation.
6. **DNS → Records** → add `AAAA` `@` → `100::`, **Proxied (orange cloud)**.
   Required because Worker routes do not create DNS records. Without it the apex
   returns error 1016.
7. **`wrangler login`** — browser OAuth approval, triggered from the IDE.
8. **Turnstile → Add widget** — name `shaxda`, hostname `shaxda.app`, Managed mode.
   Copy the site key and the secret key. Do not paste either into a tracked file.
9. **Web Analytics** (optional) — add `shaxda.app`, copy the beacon token for
   `PUBLIC_CF_BEACON_TOKEN`, or leave that variable empty.
10. **Notifications → Billing/usage alerts** per `docs/ops/billing-alerts.md`.

## 13. Rollback procedure

### Reversible

| Action                                     | Command / step                                                                                                                               | Effect                                                                                                                                           |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Roll back a Worker to the previous version | `pnpm --filter @shaxda/worker exec wrangler rollback --config wrangler.production.toml` / `pnpm --filter @shaxda/web exec wrangler rollback` | previous code live in seconds; **DO storage is untouched**                                                                                       |
| List versions first                        | `wrangler deployments list [--config …]`                                                                                                     | pick a specific version id                                                                                                                       |
| Detach the site from `shaxda.app`          | remove the `routes` entries and redeploy, or delete the route in the dashboard                                                               | traffic 404s / 522s at the edge; Workers and DO state survive                                                                                    |
| Take the apex offline entirely             | grey-cloud or delete the `AAAA @ 100::` record                                                                                               | instant; instantly reversible                                                                                                                    |
| Disable Turnstile                          | `wrangler secret delete TURNSTILE_SECRET`                                                                                                    | room creation stops requiring verification (`verifyTurnstile` returns `true` with no secret) — reduces abuse protection, does not break the site |
| Revert config                              | `git revert` the deploy commit and redeploy                                                                                                  | back to the previous topology                                                                                                                    |

**Live matches survive a code rollback.** Redeploying evicts the DO and drops open
WebSockets, but room state is in DO storage, and `OnlineGameClient` retries at
1/2/4/8/10 s and re-sends `joinRoom`, so players reconnect into the same board.
Expect a visible "reconnecting" notice for a few seconds after every deploy — deploy
during a quiet window.

### Irreversible or destructive — do not perform during rollback

| Action                                                                                                              | Consequence                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Editing `[[migrations]]` to rename or delete `MatchRoom` / `RoomCoordinator` (`renamed_classes`, `deleted_classes`) | **permanently destroys all stored room state**; every in-progress match is lost with no recovery                                                           |
| Renaming the Worker (`name = "shaxda-worker"`)                                                                      | a rename creates a _new_ script with _new_, empty DO namespaces; the old namespaces and their rooms are orphaned                                           |
| Deleting the Worker script in the dashboard                                                                         | deletes its DO namespaces and all room state                                                                                                               |
| Changing `new_sqlite_classes` to a different storage type                                                           | not supported for an existing class                                                                                                                        |
| Namecheap nameserver change                                                                                         | technically reversible, but propagation means hours of downtime each way                                                                                   |
| Removing `shaxda.app` from Cloudflare                                                                               | destroys zone config and the Universal SSL certificate; reissuing takes up to 24 h and the domain is unreachable throughout because of `.app` HSTS preload |

**Steps that cannot be rolled back:** the initial DO migrations `v1`/`v2` (they can
only be undone destructively) and the nameserver delegation (undoable only slowly).
Everything else in this plan is a config or version change that reverts cleanly.

The safe rollback for a bad launch is: `wrangler rollback` both Workers → if still
broken, remove the routes so the domain serves nothing → investigate → redeploy.
Never reach for migration edits.

## 14. Blockers and risks

**Critical**

- **R1 — Building without `web/.env.production`.** `workerOrigin.ts:1` falls back to
  `http://127.0.0.1:8787` (→ `ws://…`) and `metadata.ts:1` to `https://shaxda.example`.
  The build succeeds, the site loads, and online play is 100% broken by mixed-content
  blocking — invisible on localhost and on `*.workers.dev`. Mitigated by the mandatory
  post-build `grep` in Stage 2/5; permanently fixed by optional change O-a.
- **R2 — Turnstile half-configured.** Secret set without site key ⇒ every room creation
  returns 403 `turnstileFailed`, with a UI that shows no widget and no explanation.
  Set both keys in the same change.

**High**

- **R3 — Uncapped WebSocket connections per room.** `GET /rooms/:code/ws` has no
  connection cap and no route-level rate limit. `MatchRoom.webSocketMessage` calls
  `refreshStoredActivity()` — a storage `put` plus `setAlarm` — on **every** inbound
  message, before the join check, so even unjoined sockets drive DO writes. Per-socket
  limits exist (30 msgs / 10 s, 4 KB frames) but are per-connection, so N sockets
  multiply the load. Anyone holding a room code can amplify DO wall-clock and storage
  writes. Free mitigation available today: one Cloudflare WAF rate-limiting rule on
  `/rooms*` (free plan includes one). Code fix is optional change O-b — do not bundle
  it into the deploy.
- **R4 — Apex Worker route depends on the placeholder DNS record.** Routes do not
  create DNS. Without the proxied `AAAA @ 100::` record the whole site returns
  Cloudflare error 1016, even though both Workers deployed successfully.
- **R5 — Single global `RoomCoordinator`.** Every room creation worldwide serialises
  through one DO whose placement is decided by the first room ever created. It is a
  single point of failure and a latency floor for room creation. Acceptable at launch
  volume; revisit if creation latency becomes visible.

**Medium**

- **R6 — `/board` is publicly reachable.** It is an internal fixture/QA gallery,
  `prerender = true`, not linked from navigation or the homepage, and it returns a
  sane Somali page rather than an error. There is no `sitemap.xml` and no `robots.txt`
  in `web/static`, so there is no list to exclude it from, but search engines can
  still find it. Optional change O-c adds `noindex`. Report only.
- **R7 — Q1 and BETA1 sign-off are blank.** `docs/qa/q1-report.md` and
  `docs/qa/beta1-feedback-log.md` are unfilled templates, and
  `docs/ops/launch-runbook.md` says not to deploy until both record sign-off. This is
  a process gate Mahamed can consciously waive, not a technical blocker. Flagging it
  because the repo's own runbook forbids the deploy as written.
- **R8 — Runbook/config drift.** `docs/ops/launch-runbook.md` documents `shaxda.so` +
  `api.shaxda.so` custom domains; that is the contradiction between docs and the
  chosen topology. Resolved by change B4, not by silently picking one.
- **R9 — Every deploy drops live WebSockets.** Clients auto-reconnect, but players
  see a "reconnecting" notice. Deploy in a quiet window.
- **R10 — Two wrangler configs share the Worker name `shaxda-worker`.** A bare
  `wrangler deploy` in `worker/` (without `--config wrangler.production.toml`) would
  publish the dev config — no routes, no `ALLOWED_ORIGIN`. Always use the package
  scripts (`pnpm deploy:worker`), which pass `--config`.

**Low**

- **R11 — `www.shaxda.app` is not handled.** No route, no redirect. Optional change O-d.
- **R12 — `wrangler` is 4.107.0; 4.118.0 is available.** Dry-runs pass on the pinned
  version. Do not upgrade during launch.
- **R13 — `observability.enabled = true` on both Workers.** Workers Logs ingestion has
  a generous included allotment on Paid; watch it in the billing alerts.

## 15. Final go/no-go recommendation

**Go**, with three conditions:

1. `web/.env.production` exists and the post-build `grep` for `127.0.0.1:8787` and
   `shaxda.example` returns nothing (R1);
2. the Turnstile site key and secret are configured together, never the secret alone (R2);
3. the proxied `AAAA @ → 100::` record exists before the routes are expected to serve (R4).

Everything else is either already implemented and tested, or a post-launch
improvement that should not be bundled into the deployment change.

Two things are deliberately being launched _with_ known gaps, recorded rather than
fixed: no route-level cap on WebSocket upgrades (R3 — mitigate with a free WAF
rate-limiting rule on day one), and blank Q1/BETA1 sign-off documents that the repo's
own runbook treats as a gate (R7 — Mahamed's call to waive).
